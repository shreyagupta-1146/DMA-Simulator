DMA & System Theory

1. CPU vs DMA Mode

In CPU Only mode, every byte of data is moved by the CPU. This involves a lot of "fetching" and "decoding" instructions, causing very high CPU utilization.

In DMA Assisted mode, the CPU only starts the transfer. The 8237 DMA Controller takes over, moving data directly between memory and peripherals, freeing the CPU to do other work.

2. Control Signals (Handshaking)

HOLD: Signal from DMA to CPU requesting the System Bus.
HLDA: Signal from CPU to DMA acknowledging the request and releasing the bus.
DACK: Acknowledge signal sent by DMA to the peripheral to confirm data transfer is starting.
RD / WR: Control lines used to trigger actual memory/IO read and write operations.

3. Hardware Interrupts

An Interrupt is a high-priority signal that forces the CPU to stop its current task. When you trigger an interrupt in this app, you will observe that CPU-based transfers almost stop, whereas DMA-based transfers continue smoothly because the DMA hardware doesn't need the CPU's constant attention.
